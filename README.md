# MAX Chat — GREEN-API

Тестовое задание «Фронтенд разработчик React»: минимальный веб-интерфейс для отправки и получения текстовых сообщений в MAX через [GREEN-API](https://green-api.com/max).

**Живая версия:** https://green-api-max-chat-nu.vercel.app/

## Как это работает

1. **Вход** — пользователь вводит `idInstance` и `apiTokenInstance` своего инстанса GREEN-API. Перед входом данные проверяются вызовом `GetStateInstance`; при успехе сохраняются в `localStorage` браузера.
2. **Новый чат** — пользователь вводит номер телефона получателя (в международном формате).
3. **Чат** — отправка сообщений через метод [`SendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/); входящие сообщения получаются long-polling'ом через `ReceiveNotification`/`DeleteNotification` ([HTTP API receiving technology](https://green-api.com/v3/docs/api/receiving/technology-http-api/)). Каждое показанное входящее сообщение помечается прочитанным через `ReadChat`.

Интерфейс рассчитан на один активный чат за раз — без списка чатов, без истории между перезагрузками страницы (осознанное упрощение, т.к. задание просит «максимально простой интерфейс с минимальным набором функций»).

Навигация — через `react-router` (`/login`, `/new-chat`, `/chat/:phone`), а не самодельный `screen.name`-стейт: обычный back/forward браузера работает, и номер чата живёт в URL, а не только в памяти компонента.

## Предварительные требования

- Node.js 20+
- Готовый инстанс GREEN-API с типом MAX, **авторизованный** (к инстансу должен быть привязан реальный MAX-аккаунт — сканированием QR-кода из приложения MAX, аналогично привязке WhatsApp Web). Неавторизованный инстанс принимает вызовы `SendMessage` (возвращает `200 OK`), но сообщения никуда не доставляются и входящие уведомления не приходят.
- В настройках инстанса (`SetSettings`) должны быть включены `incomingWebhook`, `outgoingMessageWebhook`, `outgoingAPIMessageWebhook`, `stateWebhook` (значение `"yes"`) — иначе уведомления не попадают в очередь `ReceiveNotification`. Это можно сделать прямо из консоли GREEN-API (my.green-api.com) или одним вызовом `SetSettings`.

## Запуск локально

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`, введите свои `idInstance`/`apiTokenInstance`, затем номер телефона получателя.

## Деплой

Задеплоено на [Vercel](https://vercel.com) — автодеплой на каждый push в `main` через интеграцию с GitHub.

Чтобы задеплоить свою копию:

1. Зайти на [vercel.com](https://vercel.com) и войти через GitHub.
2. **Add New...** → **Project** → выбрать форкнутый/склонированный репозиторий.
3. Vercel сам определит Vite-проект — настройки по умолчанию (`npm run build`, папка `dist`) подходят без изменений.
4. **Deploy**.

`vercel.json` в репозитории уже содержит rewrite-правило для SPA-роутинга (см. ниже) — на Vercel ничего дополнительно настраивать не нужно. GREEN-API credentials задаются не на этапе деплоя, а пользователем прямо в интерфейсе при входе — никаких env-переменных в самом деплое не требуется.

Через `vercel` CLI (альтернатива консоли): `npm i -g vercel`, затем `vercel login` и `vercel --prod` из корня репозитория.

## Известные ограничения и технические заметки

- **Хранение**: сообщения существуют только в памяти вкладки и теряются при перезагрузке страницы. Учётные данные GREEN-API сохраняются в `localStorage` (кнопка «Сменить аккаунт» их очищает) — осознанный выбор в пользу удобства для ревьюера, а не дефолт по незнанию.
- **chatId для MAX**: при отправке (`SendMessage`) и в `senderData.senderPhoneNumber` входящих уведомлений используется номер телефона в формате `{телефон}@c.us` / чистых цифр — подтверждено на реальном авторизованном инстансе. Но `senderData.chatId` и параметр `chatId` метода `ReadChat` — это другое: непрозрачный внутренний ID MAX (например, `"468995439"`), а не `{телефон}@c.us`. Передача `{телефон}@c.us` в `ReadChat` не вызывает ошибку, а просто молча ничего не делает (`{"setRead": false}`). Это расхождение не задокументировано в публичных доках GREEN-API и было обнаружено эмпирически.
- **CORS**: прямые запросы из браузера к `api.green-api.com` работают без прокси — проверено как локально, так и с задеплоенного домена.
- **Тесты**: `src/api/greenApi.test.ts` закрепляет парсинг входящих уведомлений фикстурами с реальным payload'ом (включая расхождение выше); `src/hooks/useChatSession.test.ts` тестирует хук через `renderHook` с подменяемыми зависимостями, без моков модулей.
- **SPA-роутинг на статическом хостинге**: `vercel.json` переписывает любой путь на `index.html`, иначе прямой переход или reload на `/new-chat` или `/chat/:phone` отдавал бы 404 от статического хостинга. При деплое не на Vercel нужен аналогичный rewrite (например, `_redirects` на Netlify).
